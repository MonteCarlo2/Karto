# Реклама (раздел «Продвижение»): что делает JVO и что можем мы через WB API

Источники: справка JVO (Агент рекламы, Дашборд рекламы, Метрики рекламы, Автопополнение, Массовое создание, Чёрный/белый списки кластеров) и документация WB «Продвижение» (dev.wildberries.ru/docs/openapi/promotion), прочитанные 16.10.2026.

Правило проекта: всё, что можно сделать через WB API, делаем (с подтверждением продавца и журналом); что нельзя — рекомендация с цифрами и инструкцией. Деньги и записи в кабинет только после явного «Применить».

## Что мы можем сделать лучше JVO
- Советовать рекламу от маржи: допустимый ДРР берётся из «маржи на 1 продажу» товара, а не из общих порогов. Товар с отрицательной маржой в рекламу не рекомендуем.
- Тревога «закончился бюджет» по остатку бюджета кампании, а не по «балансу» (у JVO-подобных систем частая ложная тревога).
- Каждое рекомендованное действие: факт → расчёт → бюджет и срок → что нажать; запись в WB только после подтверждения.

## Рекламный агент (проект, ждёт интерфейса)

Идея JVO: агент работает по правилам «если X, то Y» и пишет каждое действие в журнал. Мы делаем так же, но осторожнее: у правила два режима, **«предлагать»** (по умолчанию, человек нажимает кнопку) и **«автопилот»** (только в рамках лимитов правила).

Что уже есть (код, без базы):
- `ads-agent.ts`: правило автопополнения и его проверка (`evaluateAutopay`): порог остатка бюджета кампании, сумма пополнения, **суточный лимит на кампанию** (без него правило не работает), не больше, чем на счёте продвижения; делит счёт между кампаниями по порядку; при неизвестном счёте не пополняет и объясняет причину. Покрыто тестами.
- Границы исполнения те же, что у ручных кнопок: сумма целая, ≤ 100 000 ₽, источник только счёт продвижения, без повторов при таймауте.

Что в базе (миграция `supabase/migrations/20261016_seller_hub_agents_cache.sql`, применена 16.10.2026; подробности в `docs/seller-hub/data-in-supabase.md`):
- Общая база для всех будущих агентов (реклама, цены, ответы, остатки), а не только для рекламы:
  - `seller_hub_agent_rules`: правила пользователя (агент, вид, режим, параметры, включено; по умолчанию выключены и в режиме «предлагать»);
  - `seller_hub_agent_actions`: журнал действий (агент, кто, что, когда, результат, чем инициировано). Из него считается «пополнено сегодня» для суточного лимита;
  - `seller_hub_warehouse_settings`: ручные настройки складов WB для логистики (деактивация склада и исключение остатков с даты).
- RLS как у `seller_hub_task_settings`: пользователь видит и меняет только свои строки.

Что нужно от сервера для автопилота: фоновая задача раз в 15 минут (отдельная от «Автоотзывов», её код и таблицы не трогаем), которая читает токен продавца через серверное хранилище Seller Hub, проверяет правила и исполняет только режим `auto`. Пока одобрена только часть «предлагать» (интерфейс правил и журнал), автопилот — отдельным решением.

## Ограничения, о которых нужно помнить
- fullstats: 3 запроса в минуту (на базовом токене 1 в час). Клиент кэширует ответ на 5 минут и не дублирует запросы.
- Статистика формируется для кампаний в статусах 7, 9, 11.
- Лимит ответа WB по рекламе ретроспективно ограничен (у JVO: 30 дней).

## Комплексный анализ нейросетью (17.10.2026)

Принцип: платформа разбирает каждую кампанию и каждый товар по цифрам и предлагает наборы действий на выбор; исполняет агент после подтверждения. Нейросеть выбирает только из закрытого списка вариантов; все числа в действиях (ставка, пополнение, цена) считает программа; вариант, не применимый к фактам (например, поднять ставку, которая уже выше конкурентной), отбрасывается до показа.

- **Разбор кампаний** («Продвижение» → Обзор): вердикт (работает хорошо, можно улучшить, невыгодна, мало данных), итог по цифрам, до трёх вариантов: ничего не менять, подождать, пауза, пополнить, снизить/поднять ставку, убрать товар, снизить цену, войти в акцию, улучшить карточку, создать кампанию с оплатой за клик (совет: тип оплаты у существующей кампании WB не меняет). Платно, около $0,0025 за весь разбор, хранится по отпечатку цифр.
- **План по проблемным карточкам** («Продвижение» → Карточки и покупатели → Карточки): вероятная причина по воронке и варианты: указать себестоимость, тестовая реклама, снизить цену (шаг 5%, не ниже безубыточной с подушкой 5%, скидка продавца сохраняется), акция, фото, текст, пополнить запас. Около $0,0007 за товар.
- **Агент** (раздел «Агенты»): пять правил, предложения «выполнить», журнал; автопилот автопополнения через серверный проход.
- Следующий шаг: ежедневный серверный разбор без открытия страницы (нужно вынести сбор фактов на сервер) и уведомления.
