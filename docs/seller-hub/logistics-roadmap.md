# Логистика и поставки: JVO «Логистика PRO» ↔ WB API ↔ KARTO

Источники: справка JVO (Логистика PRO, «Сформировать отгрузку» / Подсортировщик, «Безопасное хранение», «Учёт складов при расчёте оборачиваемости», «Управление складами») и спецификации WB (`07-orders-fbw`, `11-analytics`, `12-reports`), прочитанные 16.10.2026.

Правила проекта: только данные WB и ввод продавца; ничего не выдумываем. Запись в WB только после подтверждения.

## Матрица

| Функция JVO | Источник данных WB | Статус KARTO |
|---|---|---|
| Остатки по складам WB, в пути к клиенту / от клиента | `POST /api/analytics/v1/stocks-report/wb-warehouses` (данные раз в 30 минут) | **Сделано**: вкладка «Склады» (остаток, число артикулов, в пути, доля остатка) |
| Спрос по регионам покупателей | `GET /api/v1/supplier/orders` (Statistics, 1 запрос в минуту, 90 дней): округ и область покупателя, отмены | **Сделано**: вкладка «Регионы» (доля спроса по округам, без отмен, период 30/60/90 дней) |
| Региональные отгрузки: «где спрос больше остатка» | заказы по регионам + остатки по складам | **Сделано**: колонка «Разрыв» (доля спроса минус доля остатка в округе, п. п.). У JVO это ML по данным конкурентов; у нас по вашим реальным заказам |
| Подсортировщик: что и сколько отгрузить | заказы по округам, остатки складов, параметры продавца | **Сделано (v1)**: вкладка «Отгрузка». Нужный запас = заказов в день по округу × дни запаса − остаток склада WB округа, вверх до кратности короба; рядом остаток на вашем складе; скачивание CSV |
| Период анализа спроса, сглаживание пиков | заказы за 30/60/90 дней | Период выбирается; сглаживание пиков пока нет (среднее за период) |
| Тип поставки (короба / монопаллеты) и коэффициенты приёмки | `POST /api/v1/acceptance/options`, `GET /api/v1/warehouses` | **Недоступно:** WB временно отключил оба метода (release-notes 570). Вернутся методы — подключим выбор склада и даты по коэффициентам |
| «Безопасное хранение» (не более 15% запаса SKU на одном складе, исключение ТОП-складов) | остатки по складам | Не сделано: нужна привязка «округ → склад отгрузки» |
| Товары в пути (поставки FBW, импорт файлов) | `POST /api/v1/supplies`, `GET /api/v1/supplies/{ID}/goods` | Не сделано; у вашего токена категория поставок отмечена как недоступная |
| Управление складами: деактивировать, исключить остатки с даты | настройки пользователя | Не сделано: нужна таблица `seller_hub_warehouse_settings` (применена) |
| Оборачиваемость по «склад + баркод» с исключением дней без остатка | остатки по дням (история) | Часть: дни хватит считаются в «Остатки»; поштучная по складам нет |
| Задачи: OOS за 30 и 14 дней | спрос и остатки | **Сделано** вкладка «Риски OOS»: общий остаток (склады WB + ваш склад) ÷ спрос в день; 14 дней — отгружать, 30 дней — заказывать или производить. В «Задачи» не выводим, чтобы не трогать утверждённый движок задач |
| Задачи: низкая оборачиваемость, падение выкупа с причинами | задачи Seller Hub | Частично есть в задачах (остаток, излишек, выкуп) |
| Excel по предиктивным отгрузкам | — | Сделано в виде CSV по плану отгрузки |

## Что мы можем сделать лучше JVO
- Региональные рекомендации из ваших реальных заказов, а не из оценок по конкурентам.
- В плане отгрузки сразу видно, хватает ли остатка на вашем складе (FBS) для отгрузки на WB.
- Честные пустые состояния: если вы на FBS и у WB остатков нет, экран объясняет это, а не показывает пустую таблицу.

## Наблюдения по вашему кабинету (16.10)
- Вы работаете преимущественно с FBS: на складах WB 6 шт. (один виртуальный «Склад WB», 24 шт. в пути к клиенту), у вас на складе около 4 266 шт.
- Спрос по округам за 30 дней (149 заказов без отмен): Центральный 32,2%, Сибирский 17,4%, Южный 14,8%, Приволжский 11,4%, Северо-Западный 7,4%, Дальневосточный 6,0%, Северо-Кавказский 5,4%, Уральский 4,0%.
- План отгрузки в FBO на 45 дней: 252 шт. по 76 позициям (при FBS-модели это справка, а не обязательная отгрузка).

## Дальше

2. Привязка «округ → склад отгрузки» (по складам, где уже есть остаток, и по списку складов WB) и режим «безопасное хранение».
3. Коэффициенты приёмки и выбор даты (`acceptance/options`) и тип поставки: ждём возвращения методов WB.
4. Настройки складов (нужна миграция) и их учёт в планах и задачах.
5. Вынести риски OOS и недообеспеченные округа в «Задачи» (решение владельца, трогает движок задач).
