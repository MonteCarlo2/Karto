# Seller Hub vs JVO (Дживио): разрыв функций и план на месяц

Дата: 2026-10-16. Источник по JVO: справочный центр jvo.ru/help (страницы Мониторинг, Настройка и выполнение задач, Все артикулы, Страница товара, События, Дашборд, Сводка). Колонка «Сейчас в KARTO» заполнена только по тому, что видно в интерфейсе на живом кабинете 16.10; где не проверял, стоит «не проверено».

Правила, которые не меняем: маржа = цена − услуги WB − себестоимость (без налога, рекламы, штрафов; штрафы отдельно). Веса `priority.ts` и утверждённые формулы не трогаем. Любая запись в WB (цена, акция, остатки, реклама) только после явного подтверждения продавца и с журналом.

## Где мы можем быть сильнее JVO
- Сверка с банком: каждая цифра маржи проверяется до рубля (экран «Проверка расчётов»). У JVO этой проверки на странице не видно.
- «Деньги и доказательство» в каждой задаче: факт → расчёт → действие, без выдуманных чисел.
- Действие в одну кнопку после согласия продавца: цена, акция, остаток. Это ядро идеи «менеджер, который не спит».

## План на 4 недели (черновик)

**Неделя 1. Основа и мониторинг.**
1. Закрыть этап 1 (общая проверка: сделано, остались сверка месяца и доп. контрольные значения).
2. Диаграмма «раздел × критичность» в Задачах (кликабельная).
3. Откладывание задачи на выбранный период, в том числе поартикульно.
4. Подсказки с формулами у метрик Обзора и выбор периода.

**Неделя 2. Товары и план-факт.**
1. Матрица «Товары»: период, динамика, сохраняемые виды столбцов, фильтр по интервалам.
2. Страница товара: вкладка «Остатки по складам» и OOS (недополученная прибыль).
3. План-факт (цели, прогноз, задача «отстаём»).
4. Загрузка себестоимости файлом.

**Неделя 3. Уведомления и действия.**
1. Telegram-уведомления (красные задачи, акции, остатки).
2. Действие «Привести цену к цели» с подтверждением и журналом (на базе `price-write.ts`).
3. Рекомендатор отгрузки (остатки + темп продаж).

**Неделя 4. Агенты и полировка.**
1. Агент цен: сценарии по расписанию.
2. Реклама: после выдачи права токену.
3. Онбординг (чек-лист подключения), проверка на нового клиента, финальная проверка расчётов.

## Что исправлено 16.10 в ходе проверки
- Реклама: чтение кампаний переведено на актуальный `GET /api/advert/v2/adverts` (старый `/adv/v2/adverts` отвечал 404, ошибка глоталась). Кнопки пауза/старт переведены на `/adv/v0/pause|start`. Это записи в WB, вживую не проверялись.
- Не тронуто: `updateWbAdBudget` (`/adv/v1/budget/daily`). В документации WB этот метод заменён на `PUT /api/advert/v0/daily-limits` (тело: advertIds, enabled, dailyLimit ≥ 1000, carryOverEnabled), смысл параметров другой. Менять после решения владельца и пробы на тестовой кампании.
- Обзор: сравнение «день к дню» теперь по двум последним полным дням (по Москве), раньше сравнивался неполный сегодняшний день.
- Открыто: «Выкуп» на Обзоре = выкупы ÷ заказы за 7 дней, занижен из-за заказов в пути. Предложено считать по завершённым заказам.
- Реклама, деньги (по документации WB): `balance` — лимит оплаты по взаиморасчёту (пополнить нельзя), `net` — счёт продвижения (пополняет продавец), `bonus` — бонусы. Показы идут из бюджета кампании (`POST /api/advert/v2/budget`). Прежняя карточка «Реклама при нулевом балансе» была ложной тревогой: balance = 0, но на счёте 17 212 ₽ и у кампаний 3 102 ₽ и 718 ₽. Теперь тревога только у активной кампании с бюджетом 0 ₽. Пополнение бюджета кампании в WB API есть (`POST /adv/v1/budget/deposit`, списывает деньги со счёта/баланса/бонусов); в продукте пока только рекомендация, кнопка «Пополнить» ждёт решения владельца (движение денег, проверить можно только на реальном платеже).
- «Выкуп» на Обзоре теперь = выкупы ÷ (выкупы + отмены) за окно воронки WB (заказы в пути не считаются): 83,7% вместо 5,2%.
- Данные WB `officeMissingTimeDays` (дни отсутствия на складах) в проекте намеренно не превращаются в «дни наличия» (неоднозначны по складам, см. `task-engine/types.ts`), поэтому вкладку «Остатки по складам / OOS» строим по остаткам и упущенным заказам WB, а не по этому полю.
